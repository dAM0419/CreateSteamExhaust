# Create: Steam Exhaust

Create 보일러가 **증기를 실제로 배출해야만** 출력을 내도록 만드는 애드온입니다.
증기는 탱크 윗면에서 출발해 배관을 타고 배기 파이프의 출구로 나가며, 배관이 길수록 식어서 처리량이 줄어듭니다.
배기가 전혀 안 되면 보일러는 멈추고, 과열 끝에 폭발합니다.

| 항목 | 값 |
|---|---|
| mod id | `steamexhaust` |
| 현재 버전 | **0.1.6** |
| 대상 | Minecraft 1.21.1, NeoForge 21.1.x |
| 필수 의존 | Create 6.0.x (6.0.10 기준으로 개발) |
| 선택 호환 | Create Aeronautics (Steam Vent), Create: Connected (Fluid Vessel) |
| 함께 쓰지 않음 | Create: Smoke Stacks (같은 역할, 설치 시 경고) |

### 0.1.1 — 2026-11-09
**증기 연출**
- 증기 양을 크게 늘림. 0.1.0은 Create: Smoke Stacks보다 화면에 보이는 증기가 저출력에서 20~30배, 고출력에서 약 2.3배 적었음.
  - 덩어리 지름 0.24~0.4블록 → 0.6~1.4블록으로 시작해서, 떠오르며 2.6~4배로 부풀어 위쪽이 뭉게뭉게 퍼짐.
  - 수명 28~42틱 → 80~310틱, 불투명도 0.5(계속 옅어짐) → 0.85(수명의 55%까지 유지).
  - 출구당 틱마다 덩어리 수 = 0.08 + 0.006 × 배기량(mB/틱). 기둥 높이는 레벨 1에서 약 7블록, 출구 최대치에서 약 27블록.
- 파티클 텍스처를 꽉 찬 하얀 뭉게구름 12종으로 새로 그림 (채움 5~14% → 약 46%).
- 작은 증기 / 큰 기둥 두 종류였던 파티클을 하나로 합침. 출구 배기량에 따라 크기·수명·상승 속도가 연속으로 변함 (`tall_steam_plume` 삭제).
- 증기 파티클이 바닐라 모닥불 연기(`CampfireSmokeParticle`)를 상속함. 바닐라 처리를 먼저 돌리고 감속·부력·팽창을 덧붙이므로, 모닥불 연기를 건드리는 모드(바람 모드 등)의 효과가 증기에도 적용됨. 텍스처는 하얀 자체 텍스처 유지.
- 증기를 거리 제한 없이 그림 (굴뚝 연기처럼 멀리서도 보임). 비디오 설정의 파티클 단계(모두/감소/최소 = 1/0.5/0.2배)는 직접 반영.
- 과열 때 탱크 이음새에서 새는 증기는 바닐라 구름(`CLOUD`) 파티클로 바꿈.

**고글 표시**
- 버그 수정: "보일러 상태: 레벨 n"과 피로도 용량이 배기 상한을 반영하지 않던 문제. Create가 이 둘을 출력 계산 경로가 아니라 열·물·크기에서 직접 다시 계산하기 때문이었음. 표시용 계산에도 배기 상한을 걸었음. 실제 엔진 출력에는 원래부터 반영되어 있었음.
- 버그 수정: 실제로 출력이 깎이지 않는데 "배기 부족으로 출력 제한"이 뜨던 문제. 실제 출력은 min(보일러 레벨, 엔진·vent 수)만큼만 쓰이므로, 배기 레벨이 그보다 낮을 때만 이 문구를 띄움.
- 새 상태: 엔진은 전부 돌지만 보일러 레벨보다 배기 레벨이 낮으면 노란색 "엔진 n개까지 전부 가동 (더 달면 배기 부족)".

## 빌드

Windows에서는 `build.bat`을 더블클릭하거나, 이 폴더에서 cmd로 `gradlew build`를 실행합니다.
결과물은 `build\libs\steamexhaust-<버전>.jar`이고, 이것을 mods 폴더에 넣습니다. 이전 버전 jar는 mods 폴더에서 빼 주세요.

- Java 21이 필요합니다 (Gradle toolchain이 자동으로 찾거나 내려받습니다).
- Gradle 9.2.1 wrapper, NeoForge ModDevGradle 2.0.148을 씁니다.
- `libs/`에는 컴파일에만 쓰는 jar가 들어 있습니다: Create 6.0.10과 그 안에 포함된 Ponder, Flywheel, Registrate. 결과 jar에는 들어가지 않습니다. 각 jar는 원 저작자의 라이선스(Create·Flywheel·Ponder: MIT, Registrate: MPL-2.0)를 따릅니다.

## 게임 규칙

단위는 모두 mB/틱입니다. Create에서 보일러 레벨 n은 물 10n mB/틱에 해당하며, 증기량도 같은 단위로 셉니다.

### 용어
| 용어 | 뜻 |
|---|---|
| 보일러 | Create BoilerData가 활성인 탱크 중 증기 소비자(엔진 또는 Aeronautics vent)가 1개 이상 붙은 것 |
| 윗면 | 탱크 묶음 맨 위 층 바로 위 칸들 |
| 증기 라인 | 윗면에서 출발해 펌프를 지나지 않고 닿는 배관 묶음 1개 |
| 출구 | 연결이 정확히 1개인 배기 파이프의, 연결면 반대편 면 |
| 거리 d | 진입 칸부터 그 블록까지 최단 경로의 칸 수. 탱크 바로 위 출구는 d = 0 |
| n원래 | 배기를 빼고 계산한 보일러 레벨 = min(열, 물, 크기/4) |
| C | 보일러의 총 배기 처리량 |

### 배기 파이프
- 12px 굵기(2~14)의 어두운 구리 관. Create 유체 파이프(8px)보다 양쪽으로 2px씩 굵습니다.
- 유체는 옮기지 못하고 증기 라인의 경로와 출구 역할만 합니다.
- Create 유체 파이프와 똑같이 6방향 자동 연결됩니다. 직선, ㄱ, T, 十, 누운 S, ㅁ자 순환, 아래 방향 모두 됩니다.
- 텍스처는 관 길이 방향으로 일정해서 이어진 배기 파이프는 이음새 없이 매끈하게 이어집니다. ㄱ·T·十자로 꺾이는 곳은 줄무늬가 45° 대각선에서 맞물려 이어집니다.
- 면마다 상태가 있습니다.

| 면 상태 | 모양 |
|---|---|
| `exhaust` (배기 파이프와 연결) | 관이 경계까지 이어짐, 이음새 없음 |
| `pipe` (Create 배관·탱크와 연결) | 막힌 마감면. 더 가는 파이프가 구멍을 가린 모양 |
| `open` | 출구: 안지름 8px 구멍. 연결이 1개뿐이면 그 반대편이 이렇게 됨 (Create 파이프의 열린 끝과 같은 규칙) |
| `none` | 막힌 옆면 |

- 유체 파이프 사이에 끼인 배기 파이프는 어느 면에도 구멍이 없습니다.
- **렌치**: Create가 유체 파이프를 유리 파이프로 바꾸듯, 옆면을 렌치로 치면 **직선 배기 파이프**(축 고정, 축 방향으로만 연결)가 됩니다. 다시 치면 돌아옵니다. 탱크 위에 굴뚝 2개를 나란히 세우면 서로 붙어서 라인 1개가 되는데, 한쪽을 직선으로 바꾸면 라인 2개로 갈라집니다.
- 출구 앞을 블록이 막고 있으면(`isFaceSturdy`) 막힌 출구로 보고 처리량 0입니다.
- 제작: 유체 파이프 1 + 구리 판 1 → 배기 파이프 1 (무형). Create 크리에이티브 탭의 유체 파이프 다음에 있습니다.

### 증기 라인 판정
- 윗면 칸마다 탱크 쪽으로 열린 배관을 진입 칸(d = 0)으로 모아 너비 우선 탐색합니다. 방문 기록이 있어 ㅁ자 순환도 끝납니다.
- 양쪽이 서로를 향해 열려 있어야 이어진 것으로 봅니다. 닫힌 밸브는 증기를 막습니다.
- 탐색은 20틱마다, 보일러당 최대 2048칸입니다.

| 만난 것 | 분류 |
|---|---|
| 배기 파이프 출구 | 배기 |
| 펌프 흡입구 | 복수기 |
| 펌프 토출구 | **급수 혼입**: 그 라인 처리량 0 (물이 증기 라인으로 들어오는 중) |
| 다른 보일러의 윗면 | 공유 라인 (처리량을 수요 비율로 나눔) |
| 가열 중이고 소비자 없는 탱크의 윗면 외 면 | 재열기 |
| 그 밖의 탱크 면, 일반 파이프의 열린 끝 | 막힘. 배기는 배기 파이프 출구로만 됨 |

급수 라인은 보일러 쪽으로 물을 미는 펌프를 반드시 가지므로, 윗면 탐색이 펌프 토출구에 닿으면 그 묶음은 급수 라인입니다. 급수 배관과 배기 배관이 자동 연결로 붙어 버리면 고글에 "급수 혼입"이 뜹니다.

### 처리량과 출력
기준값 **A = 128**, **B = 4**.

- 출구 i: `cᵢ = max(0, A − B·dᵢ)`
- 라인 k: `Cₖ = min(A, Σcᵢ)` — 라인 하나는 관 하나의 단면이라 A를 넘지 못합니다. 더 필요하면 윗면에 라인을 따로 더 꽂습니다.
- 보일러: `C = ΣCₖ`
- 보일러 레벨 = `min(열, 물, 크기/4, ⌊C/10⌋)` — 배기가 Create 레벨 공식의 네 번째 병목입니다.

근거: Create 펌프 유량은 (RPM ÷ 분기 수) ÷ 2이고 최대 256 RPM이므로 펌프 1대 최대 128 mB/틱 = A = 레벨 12. B = 4면 32블록에서 다 식습니다.

라인 1개의 허용 거리 `d_max(n) = ⌊(128 − 10n) ÷ 4⌋`:

| 레벨 n | 필요 처리량 | 허용 거리 |
|---|---|---|
| 1 | 10 | 29 |
| 3 | 30 | 24 |
| 6 | 60 | 17 |
| 9 | 90 | 9 |
| 12 | 120 | 2 |
| 13~18 | 130~180 | 라인 2개 이상 |

- 급수가 배기보다 많으면 레벨이 C에 묶이고 남는 급수는 버려집니다 (효율 저하).
- 실제 엔진 출력은 레벨 하나당 엔진 하나입니다. 그래서 배기 레벨이 엔진 수 이상이면 출력은 깎이지 않습니다.
- 여러 보일러가 라인 하나를 공유하면 처리량을 수요(10·n원래) 비율로 나눕니다.
- 증기 소비자가 없는 보일러(휘슬만 단 경우)는 배기 규칙에서 빠집니다.

### 복수기
증기 라인이 펌프 흡입구에 닿고, 그 펌프가 물을 보일러로 밀면 복수기입니다. 배관에서 응축된 물의 η(기본 0.95)만큼을 급수로 돌려줍니다.

- 경로 처리량: `c = min(A, B·d, RPM ÷ 2)` — d는 진입 칸에서 펌프까지 거리.
- 회수량 = η × (그 경로로 실제로 간 증기). 처리량이 아니라 생산된 증기 기준이라 생산보다 많이 돌려받지 않습니다.
- 회수 대상: 펌프 토출구에서 배관을 따라(펌프 사거리 안) 처음 닿는 보일러. **윗면이 아닌 면**으로 들어가야 합니다 (윗면으로 들어가면 급수 혼입).
- 실제 유체는 옮기지 않고 대상 보일러의 급수 집계에 더합니다. 처음 가동할 때는 외부 급수가 꼭 있어야 하고, η < 1이라 외부 급수를 끊으면 레벨이 천천히 내려갑니다.
- 예: 레벨 12 보일러의 물 120 mB/틱을 복수기 하나로 받으려면 d ≥ 30, 펌프 240 RPM 이상. 외부 급수는 6 mB/틱으로 줄어듭니다.

### 재열기
증기 라인 중간에 가열된 탱크(엔진 없음, 밑에 열원)를 두면 증기를 다시 데워 거리를 0부터 다시 셉니다. 지하 기지의 증기를 지표로 끌어올리는 용도입니다.

- 상류에서 재열기의 처리량: `c_R = min(10·h_R, C_하류)` — h_R은 재열기 열 레벨(크기/4로 제한), C_하류는 재열기 윗면에서 다시 탐색한 처리량.
- 상류 거리는 처리량을 줄이지 않습니다 (대가는 재열기 버너 연료).
- 최대 8단까지 연달아 거칠 수 있습니다.
- 예: 지하 40블록의 레벨 6 보일러 → 30블록 → h_R = 6인 재열기 → 17블록 안의 출구 → 지표 배출.

### 과열과 폭발
- **배기 없음** = 증기 소비자 ≥ 1, n원래 ≥ 1, **C = 0**. 이 동안 매 틱 과열값에 n원래를 더하고 1200에 닿으면 폭발합니다. 배기가 되거나 보일러가 쉬면 매 틱 20씩 줄어듭니다.
- 배기가 모자란 것(0 < C < 10·n원래)은 과열이 아니라 출력 제한입니다.

| n원래 | 1 | 2 | 3 | 6 | 9 | 12 | 18 |
|---|---|---|---|---|---|---|---|
| 폭발까지 (초) | 60 | 30 | 20 | 10 | 6.7 | 5 | 3.3 |

- 경고: 1% 이상 고글에 과열 %와 새는 증기, 25% 이상 쉬익·삐걱 소리, 75% 이상 경보음.
- 위력 = `min(6, 2 + 0.2 × n원래 × √(탱크 칸 수 ÷ 4))`. 블록 파괴는 설정으로 끌 수 있습니다.
- 보호 규칙
  - **유예**: 모드 설치 전에 저장된 보일러는 배기가 한 번 유효해질 때까지 과열되지 않습니다 (설치 직후 월드의 모든 보일러가 터지는 것 방지).
  - **알 수 없음**: 배기 라인이 로드되지 않은 청크에 닿으면 직전 처리량을 유지하고 과열을 쌓지 않습니다.

### 연출
- 서버가 출구별 배출량을 동기화하고, 클라이언트는 그 양에 비례해 증기를 뿜습니다. 복수기·재열기로 간 몫은 파티클을 내지 않습니다.
- 출구당 틱마다 덩어리 수 = 0.08 + 0.006 × 배기량. 분출 속도는 출구 부하율에 비례하고, 이후 부력으로 떠오르며 부풉니다. 아래를 향한 출구의 증기는 내려갔다가 말려 올라갑니다.
- 출구마다 낮은 쉬익 소리.

### 고글
Create 보일러 표시 밑에 줄이 붙습니다.
- 처리량: 배기 레벨 ⌊C/10⌋과 C (mB/틱)
- 상태 (해당할 때만): 배기 부족으로 출력 제한 / 엔진 n개까지 전부 가동 / 배기 없음 / 급수 혼입 / 출구 막힘 / 거리 초과 / 복수 펌프 정지 / 알 수 없음 / 유예
- 과열 %, 복수 회수량

## 호환

선택 호환은 모두 런타임에 감지하며, 해당 모드가 없으면 그 Mixin은 건너뜁니다.

| 대상 | 처리 |
|---|---|
| **Create Aeronautics** Steam Vent | 탱크 윗면 vent는 처리량 10 × 신호/15인 d = 0 출구. 양력 = min(스크롤 값, 500 × 그 vent로 간 증기). 기본 5000 m³ = 레벨 1이라 Aeronautics 기본 균형과 같음. `pipeFedVents`를 켜면 배기 라인 끝 vent도 양력 = min(스크롤, 250 × 증기). 닫힌 vent는 `closedVentRelief`로 처리량 10을 인정해 하강하는 비행선 보호 |
| **Create: Connected** Fluid Vessel | 자체 BoilerData 하위 클래스를 쓰므로 같은 Mixin을 따로 걺. Create 탱크와 같은 출력 제한·과열·고글 |
| Create: Smoke Stacks | discouraged 의존성으로 경고만 띄움. 그 연도관은 배기로 인정되지 않음 |
| 휘슬 | 소비자 없는 보일러는 배기 규칙 제외 |
| Sable 구조물 위 보일러 | 별도 처리 없음 (블록 엔티티의 레벨 안에서 동작) |

## 구현 구조

```
com.ssw.steamexhaust
├─ SteamExhaust, SERegistry          모드 진입점, 블록·아이템·블록 엔티티·파티클 등록, 유체 capability
├─ config/SEConfig                   서버·클라이언트 설정
├─ content/                          배기 파이프, 직선 배기 파이프, 면 상태, 빈 블록 엔티티, 증기 파티클 인자
├─ steam/
│  ├─ SteamSearch                    증기 라인 탐색, 끝점 분류
│  ├─ SteamExhaustTicker             처리량·배분·복수 회수·과열·폭발·동기화
│  ├─ SteamState                     보일러에 붙는 배기 상태 (NBT 저장·동기화)
│  ├─ BoilerGeometry, BoilerHooks    탱크 윗면·크기, Mixin 공통 로직
│  └─ GoggleLines, SteamClientEffects 고글 줄, 증기·소리 연출
├─ client/                           파티클 클래스·등록
├─ compat/AeroCompat                 Aeronautics 감지
└─ mixin/
   ├─ BoilerDataMixin                getActualHeat·getEngineEfficiency·고글 표시 레벨에 배기 상한, NBT
   ├─ FluidTankBlockEntityMixin      탱크 틱, 고글 줄 추가
   └─ compat/                        Fluid Vessel, Aeronautics Steam Vent (조건부)
```

Create 탱크가 Create 파이프에 붙도록 배기 파이프는 용량 0인 유체 capability를 노출합니다 (Create 6.0.10은 블록 엔티티가 없으면 capability를 묻지 않으므로 빈 블록 엔티티가 있음).
